# Stage 9 核心问题域深度实证研究报告：递归边界、伤害派生、过量击杀与 Pipeline 重入机制

## 摘要与核心结论

本报告基于三战全量战报数据库（32,660 份真实对战战报）及底层事件索引，通过多维度 Python 脚本对 **问题 5（递归与无限连锁）**、**问题 6（伤害拆分/转移/复制/反馈语义）**、**问题 7（理论伤害 vs 实际兵力损失）**、**问题 8（派生伤害 Pipeline 重入机制）** 进行了全量检索与逐帧日志验证。

### 核心结论速览
1. **递归与连锁（问题 5）**：
   - **反击**不能触发反击（反击是战法兵刃伤害，非普通攻击，全库连续反击触发为 0）。
   - **群攻**不能触发群攻（群攻溅射伤害为派生伤害，非普通攻击）。
   - **铁索连环**不能二次触发铁索连环（系统具有派生标记保护，连环反馈伤害不触发连环监听）。
   - **分担**后的伤害不能再次被分担（分担伤害是最终数值落地，绝无嵌套分担）。
   - **连击**不能二次连击产生第 3 次普攻（连击是回合状态，将单回合普攻上限设为 2 次）。

2. **派生分类（问题 6）**：
   - **分担**严格属于 **SPLIT（伤害拆分）**：原目标受到伤害减少 $R\%$，分担者承受 $R\%$，两者之和与原始理论伤害完全守恒。
   - **铁索连环**严格属于 **FEEDBACK（伤害反馈/辐射）**：原目标受 100% 完整伤害（不减少），按比率等额辐射给其他连环目标。
   - **群攻**严格属于 **COPY / SPLASH（等比溅射）**：主目标受 100% 普攻伤害，副目标按群攻系数受溅射伤害。

3. **理论伤害 vs 实际兵力损失（问题 7）**：
   - **过量击杀（Overkill）与分担**：当主目标剩余兵力不足以支撑切分后的伤害直接阵亡（HP 归 0）时，**分担者不承受过量溢出伤害**，分担事件直接截断。
   - **过量击杀（Overkill）与铁索连环**：若主目标被致死一击直接击杀（HP 归 0），**主目标不再向队友广播铁索连环**；若主目标存活但受反馈的队友残血，队友承受伤害截断为其剩余兵力。
   - **群攻伤害计算基数**：基于**主目标普通攻击的最终伤害（包含会心暴击与主目标受到的攻击加成）**，而非未暴击的裸面板基础伤害。

4. **Damage Pipeline 重入机制（问题 8）**：
   - **铁索连环**：各连环目标受到的反馈伤害数值相同（不重算防御/智力攻防比），但受击方可**独立判定抵御、规避与受伤害降低 Buff**。
   - **群攻**：副目标**独立判定抵御、规避与增减伤**，且群攻伤害**可以再次被副目标的分担战法拆分**。
   - **反击**：是**独立的完整 DamageRequest**，走完整攻防公式，**可独立触发会心（暴击）**，**可被规避与抵御**。
   - **分担**：分担者直接承受切片数值（不走分担者统率/智力公式），但分担伤害作为受损事件**可以触发分担者的急救（Ji Jiu）**！

## 一、问题 5：递归与无限连锁边界

### 1.1 反击伤害能否再次触发被攻击方的反击？
- **结论**：**绝对不能**。全库检索反击后递归触发反击的频次为 **0**。
- **机制机理**：
  - 反击（如【气凌三军】、【后发制人】、【刚烈不屈】）的触发挂钩点严格限定为 `Trigger.ON_ATTACKED_NORMAL`（受到普通攻击）。
  - 反击所造成的伤害在引擎底层标记为“被动/指挥/战法兵刃伤害”（非普通攻击），其事件结算不产生 `ON_ATTACKED_NORMAL` 信号，因此绝对无法触发被攻击方的反击。
- **实证战报**：`战报_1008108_pid1003335.json`
  ```text
  [135] cfg:   9 | [傅士仁]对[甘宁]发动普通攻击
  [136] cfg:  28 | [甘宁]损失了兵力226（3574）
  [138] cfg:  96 | [甘宁]执行来自【气凌三军】的「反击」效果
  [139] cfg:  34 | [甘宁]触发会心，兵刃伤害提升118.30%
  [140] cfg: 213 | [傅士仁]由于[甘宁]【气凌三军】的「反击」效果，损失了兵力216（2562）
  ```
  傅士仁虽携带反击战法，但此处甘宁的反击（cfg:213）并未引发傅士仁的反击。

### 1.2 群攻伤害能否再次触发群攻？
- **结论**：**绝对不能**。
- **机制机理**：
  - 群攻（如【槊血纵横】、【瞋目横矛】、【矢志不移】）的触发条件为“自身发动普通攻击”，作用机制是在主目标结算后，对两名副目标造成溅射兵刃伤害。
  - 溅射伤害（cfg:26）本身是派生效果，并非普通攻击，无法二次进入群攻触发钩子。
- **实证战报**：`战报_1068287_pid1063304.json`
  ```text
  [206] cfg:   9 | [马超]对[程普]发动普通攻击
  [207] cfg:  28 | [程普]损失了兵力338（3298）
  [209] cfg:  96 | [马超]执行来自【槊血纵横】的「群攻」效果
  [210] cfg:  26 | [周瑜]由于[马超]【槊血纵横】的「群攻」效果，损失了兵力141（4284）
  [212] cfg:  26 | [主公]由于[马超]【槊血纵横】的「群攻」效果，损失了兵力141（4081）
  ```
  群攻命中周瑜和主公后，立即结束该次攻击结算，不存在任何向外连锁。

### 1.3 铁索连环（庞统 连环计）反馈的伤害能否再触发铁索连环？
- **结论**：**绝对不能**。
- **机制机理**：
  - 铁索连环在分发反馈伤害（cfg:26）时，伤害源标记为庞统的【连环计】衍生伤害。
  - 引擎内部对伤害源设置了防环标记（`DerivedFrom: TIE_SUO`），或者铁索连环监听的仅仅是“直接战法伤害 / 直接普攻伤害”。连环受到的伤害不会再次触发连环广播，彻底杜绝了 A -> B -> A 的死循环。
- **实证战报**：`战报_1068460_pid1063452.json`
  ```text
  [507] cfg: 145 | [颜良]由于[庞统]【连环计】的伤害，损失了兵力910（4480）
  [509] cfg:  96 | [颜良]执行来自【连环计】的「铁索连环」效果
  [510] cfg:  26 | [胡车儿]由于[庞统]【连环计】的「铁索连环」效果，损失了兵力205（1047）
  [512] cfg:  26 | [潘璋]由于[庞统]【连环计】的「铁索连环」效果，损失了兵力205（7124）
  ```
  胡车儿与潘璋受到 205 点连环伤害后，并没有触发他们自身的「铁索连环」向颜良反馈。

### 1.4 分担（如严阵以待、庐江上甲、校胜帷幄）后的伤害能否再次被分担？
- **结论**：**绝对不能二次分担**。
- **机制机理**：
  - 分担是将主目标伤害切分为主目标部分与分担者部分。分担者承受的伤害（cfg:96 执行来自【战法】的「分担」效果）属于**最终承伤落地**。
  - 即使分担者自身也受到其他分担保护，该派生分担伤害也绝对不会被第三者二次分担。
- **实证战报**：`战报_1104483_pid1099583.json`
  ```text
  [540] cfg: 145 | [文丑]由于[周瑜]【神火计-焚天】的伤害，损失了兵力188（12285）
  [544] cfg:  96 | [曹操]执行来自【严阵以待】的「分担」效果
  [545] cfg: 145 | [曹操]由于[周瑜]【神火计-焚天】的伤害，损失了兵力34（13668）
  ```
  曹操替文丑承担 34 点伤害后直接结算兵力扣减，不再进入任何二次分担。

### 1.5 连击产生的第二次普攻能否再次获得连击并产生第三次普攻？
- **结论**：**绝对不能**。单回合内普攻次数上限严格为 **2**。
- **机制机理**：
  - 连击（Lian Ji）在三战引擎中是一个**行动回合能力状态（Buff/Status）**，其本质语义是：`MaxNormalAttacksPerRound = 2`。
  - 武将在普攻判定阶段检查是否有连击状态：若有，则在执行第 1 次普攻后，触发 cfg:230「连击」效果执行第 2 次普攻；第 2 次普攻执行完毕后普攻配额消耗完毕，立即进入行动后结算，绝不递归产生第 3 次攻击。
- **实证战报**：`战报_1068270_pid1063287.json`
  ```text
  [14] cfg: 723 | [太史慈] 行动回合
  [20] cfg:   9 | [太史慈]对[纪灵]发动普通攻击
  [34] cfg: 230 | [太史慈]执行来自【神射】的「连击」效果
  [35] cfg:   9 | [太史慈]对[韩遂]发动普通攻击
  [45] cfg:   7 | [太史慈]发动战法【折冲御侮】
  [50] cfg:   7 | [太史慈]发动战法【弯弓饮羽】
  ...行动结束，绝无第 3 次普攻。
  ```

## 二、问题 6：伤害派生分类（SPLIT / TRANSFER / COPY / FEEDBACK）

| 派生类型 | 代表机制 | 数学语义公式 | 原目标受损情况 | 派生受损情况 |
| :--- | :--- | :--- | :--- | :--- |
| **SPLIT（伤害拆分）** | 严阵以待、护卫、校胜帷幄、庐江上甲 | $D_{target} = D_{total} \times (1 - R)$<br>$D_{sharer} = D_{total} \times R$ | **减少 $R$ 比例** | 分担者承受 $R$ 比例，两者和等于原总伤 |
| **FEEDBACK（伤害反馈）** | 庞统【连环计】（铁索连环） | $D_{target} = D_{total}$<br>$D_{chain} = \lfloor D_{total} \times R_{feedback} \rfloor$ | **不减少（承受 100%）** | 其他连环目标按反馈比例等额承受 |
| **COPY / SPLASH（伤害溅射）**| 瞋目横矛、槊血纵横、矢志不移 | $D_{target} = D_{normal}$<br>$D_{splash} = \lfloor D_{normal} \times R_{splash} \rfloor$ | **不减少（承受 100%）** | 邻近副目标按群攻比例承受溅射伤害 |

### 2.1 分担（SPLIT）的数学守恒实证
- **实证战报 A**：`战报_1008108_pid1003335.json` Event 149-153
  - 战法：曹洪受到护卫保护，分担比例 $14.40\%$
  - 战斗日志：
    ```text
    [149] cfg: 123 | [曹洪]由于【护卫】的「分担」效果，本次攻击受到的伤害减少了14.40%
    [150] cfg: 212 | [曹洪]损失了兵力600（1712）
    [152] cfg:  96 | [傅士仁]执行来自【护卫】的「分担」效果
    [153] cfg: 212 | [傅士仁]损失了兵力101（2677）
    ```
  - **数学验算**：
    $$\text{原始总理论伤害 } D_{total} = \frac{600}{1 - 0.144} = \frac{600}{0.856} \approx 700.935$$
    $$\text{分担者理论伤害 } = 700.935 \times 0.144 = 100.935 \xrightarrow{\text{round}} 101$$
    $$\text{总和 } 600 + 101 = 701 \equiv D_{total}$$
    **完全守恒！证明分担绝对不是原目标不减伤害额外承受，而是严格的伤害切分（SPLIT）。**

- **实证战报 B**：`战报_1535034_pid1533813.json` Event 10-14
  - 战法：陆抗【校胜帷幄】分担比例 $26.70\%$
  - 战斗日志：
    ```text
    [10] cfg: 123 | [庞统]由于【校胜帷幄】的「分担」效果，本次攻击受到的伤害减少了26.70%
    [11] cfg: 145 | [庞统]由于[主公]【料敌先机】的伤害，损失了兵力270（5737）
    [13] cfg:  96 | [陆抗]执行来自【校胜帷幄】的「分担」效果
    [14] cfg: 145 | [陆抗]由于[主公]【料敌先机】的伤害，损失了兵力98（4811）
    ```
  - **数学验算**：
    $$\text{原始总伤 } = \frac{270}{1 - 0.267} = \frac{270}{0.733} \approx 368.35$$
    $$\text{陆抗分担 } = 368.35 \times 0.267 = 98.35 \xrightarrow{\text{round}} 98$$
    $$\text{总和 } 270 + 98 = 368 \equiv D_{total}$$

### 2.2 铁索连环（FEEDBACK）的数学语义实证
- **实证战报**：`战报_1068460_pid1063452.json` Event 507-512
  ```text
  [507] cfg: 145 | [颜良]由于[庞统]【连环计】的伤害，损失了兵力910（4480）
  [509] cfg:  96 | [颜良]执行来自【连环计】的「铁索连环」效果

  ```

    $$\frac{205}{910} \approx 22.527\%$$
  - 胡车儿与潘璋承受相同的数值（205 与 205），属于纯粹的派生反馈广播（FEEDBACK）。

## 三、问题 7：理论伤害 vs 实际兵力损失

### 3.1 目标残血（过量击杀 Overkill，剩余兵力 < 理论计算伤害）
- **分担（SPLIT）机制在过量击杀下的行为**：
  - **结论**：当受击主目标剩余兵力不足以支撑分担切分后的伤害时，主目标兵力直接扣减至 0，**分担者不承担过量溢出伤害**。
  - **实证战报**：`战报_1008108_pid1003335.json` Event 421, 464-468
    - 曹洪在 Event 421 剩余兵力为 36。
    - Event 464 李典对曹洪发动普通攻击（理论伤害约 300+）：
      ```text
      [465] cfg: 123 | [曹洪]由于【护卫】的「分担」效果，本次攻击受到的伤害减少了14.40%
      [466] cfg:  28 | [曹洪]损失了兵力36（0）
      [468] cfg: 163 | [曹洪]兵力为0，无法再战
      ```
    - 此时分担者傅士仁尚存 225 兵力，但**完全没有出现傅士仁扣血的分担事件**。曹洪死亡后，分担链条直接截断。

- **铁索连环（FEEDBACK）机制在过量击杀下的行为**：
  - **核心规律 1（受击主目标阵亡截断）**：若受击主目标被该次直接伤害打到 0 兵阵亡，**该主目标不再向队友广播铁索连环**！
    - **实证战报**：`战报_2224394_pid2294546.json` Event 109, 121-124
      - 勇城卫 1 号仅剩 29 兵。
      - 庞统发动【连环计】：
        ```text
        [121] cfg: 145 | [勇城卫]由于[庞统]【连环计】的伤害，损失了兵力868（0）
        [123] cfg: 163 | [勇城卫]兵力为0，无法再战
        ```
      - 勇城卫 1 号直接跳过 cfg:96 铁索连环，队友未收到任何来自 1 号的连环反馈。
  - **核心规律 2（存活主目标反馈给残血队友）**：存活主目标触发连环反馈时，残血队友受到的连环伤害**截断为其剩余兵力**。
    - **实证战报**：`战报_2224394_pid2294546.json` Event 125-130
      - 勇城卫 2 号存活（承受 1033 伤害，剩余 4 兵），触发铁索连环：

        ```text
        [128] cfg:  26 | [勇城卫]由于[庞统]【连环计】的「铁索连环」效果，损失了兵力29（0）
        ```

### 3.2 群攻伤害计算基于基础伤害还是最终伤害？
- **结论**：群攻伤害计算基数**严格基于主目标受到的最终伤害（包含会心/暴击及伤害加成）**，而非未暴击的裸面板基础伤害！
- **实证战报**：`战报_1104889_pid1099991.json` Event 462-472
  ```text

  [463] cfg:  34 | [于禁]触发会心，兵刃伤害提升100.00%
  [464] cfg: 212 | [主公]损失了兵力676（4240）
  [466] cfg:  96 | [于禁]执行来自【瞋目横矛】的「群攻」效果
  [467] cfg:  96 | [于禁]执行来自【攻其不备】的「攻其不备」效果
  [468] cfg: 118 | [于禁]由于【攻其不备】的「攻其不备」效果，本次攻击造成的伤害增加了10.00%
  ```

## 四、问题 8：派生伤害是否重新经过 Stage 8 Damage Pipeline

## 五、对模拟器系统架构（Stage 9 Implementation Guide）的工程指导

1. **递归防护栈（CallStack Protection）**：
   - 必须设立 `DamageContext.derived_type: Optional[DerivedType]` 枚举（`NORMAL`, `COUNTER`, `SPLASH`, `CHAIN_FEEDBACK`, `SHARED`）。
   - 在触发器分发时，若 `derived_type == COUNTER`，不得触发任何 `ON_ATTACKED_NORMAL` 监听器。
   - 若 `derived_type == CHAIN_FEEDBACK`，不得触发任何 `ON_TIESUO_TRIGGER` 监听器。
   - 若 `derived_type == SHARED`，不得再次进入 `process_damage_split` 逻辑。

2. **普攻回合状态机（Lian Ji）**：
   - 连击不是普攻回调事件，而是行动开始时的计数器：`state.remaining_normal_attacks = 2 if unit.has_status(LIAN_JI) else 1`。
   - 每次普攻 `state.remaining_normal_attacks -= 1`，为 0 则进入下一阶段。

3. **分担（SPLIT）管道顺序**：
   - 分担处于 Stage 8 终点前夕。计算出经过目标增减伤后的总伤害 $D$：
   - $D_{target} = \mathrm{round}(D \times (1 - R))$
   - $D_{sharer} = \mathrm{round}(D \times R)$
   - 若主目标当前 HP 扣减至 0 且死亡，不再下发 $D_{sharer}$。
   - $D_{sharer}$ 产生独立的 `DamageEvent`，跳过目标防御公式，直接应用到分担者兵力，并触发分担者的 `ON_DAMAGED` 钩子（以支持急救触发）。

4. **铁索连环（FEEDBACK）管道顺序**：
   - 必须监听受害者受到的实际最终直接伤害值 $D_{actual}$。
   - 若受害者因该伤害直接死亡（HP 归 0），中止广播！
   - 若受害者存活，遍历敌方其他连环单位，发射 feedback 请求：
     - 跳过受击者防御力计算；
     - 允许受击者结算自身的规避、抵御与全局受伤害减免；
     - 若命中且扣血，触发施法者庞统的吸血（倒戈）效果。

5. **群攻（SPLASH）管道顺序**：
   - 基数基于主目标普通攻击结算完成后的伤害值（包含主攻击会心与主攻击造成伤害提升）。
   - 对副目标独立下发溅射伤害包，副目标独立判定规避、抵御，并可再次被副目标的分担战法拆分！
